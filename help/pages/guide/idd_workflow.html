Issue-Driven Development (IDD)

LOGIK-PROJEKT follows an Issue-Driven Development (IDD) workflow. This methodology ensures that every change, feature, or bugfix is tracked, documented, and semantically searchable.

The Core Loop

  1. Issue Creation: Every task begins as a GitHub Issue.
  2. Branching: A feature branch is created specifically for that issue (e.g., feature/issue-42-add-mcp-tools).
  3. Context Capture: The LogTransmitterHandler and session capture scripts record the development process.
  4. Synchronization: GitHub Actions automatically sync issue status to the project's TO-DO.md file.
  5. Finalization: Insights and decisions made during the session are synthesized into the knowledge base.

AI Integration

By following IDD, we create a rich trail of data that the RAG System and MCP Server can use to assist future development. The AI can answer questions about why a certain decision was made by looking at the linked issues and session summaries.

Key Commands

# Load context for a specific issue
/ag-load-issue 42

# Sync current session insights
/ag-capture-all
Source of Truth: In IDD, the GitHub Issue is the single source of truth. The TO-DO.md file acts as a local mirror for quick reference.
